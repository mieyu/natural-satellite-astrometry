# ADIAS 程序处理第二阶段：02Detect 星象检测

## 1. 阶段目标与位置

ADIAS 的处理顺序是 `01Pre → 02Detect → 03Match → 04ComOC → 05Report`。第二阶段 `02Detect` 的任务是从每幅 CCD 图像中找出可能的星象，测量它们的像素坐标、亮度和信噪比，并生成供第三阶段使用的检测星表。它只回答“图上哪些位置存在可用的亮点”；将这些亮点与 GAIA 星表对应、求天球坐标和目标残差，是后续阶段的工作。

```text
原始 FITS / 01Pre 处理后的 FITS
              ↓
       全图背景与噪声估计
              ↓
          阈值分割
              ↓
        连通像素归组
              ↓
      修正矩计算星象中心
              ↓
      尺寸、饱和与 SNR 筛选
              ↓
      fits_reg/<原文件名>.reg
              ↓
       03Match 星象匹配归算
```

## 2. 输入从哪里来

程序先根据配置项 `1fitspath` 找到每个观测日的 `fits/` 目录，并以其中的原始 `.fit` 或 `.fits` 文件作为待处理清单。对清单里的每幅图，实际读取哪个像素文件由 `1superflag` 决定：

| `1superflag` | 02Detect 读取的图像 |
|---|---|
| `0` | 原始 `fits/<name>.fit`；预处理被跳过。 |
| `1`、`2`、`3` | 第一阶段生成的 `fits_n/<name>_n.fit`。 |

也就是说，原始文件名负责确定处理清单和输出文件名；启用预处理时，检测的像素来自 `_n` 图。如果配置要求预处理图但该文件不存在，当前帧会记录为缺失输入，不会自动回退到原始图。读取时，FITS 主 HDU 的像素阵列转换为 `float64`，同时保留头信息中的 `BITPIX` 用于饱和判断。算法预期输入是二维图像。

## 3. 一幅图像如何变成候选星象

### 3.1 估计整幅图的背景水平

首先调用 `calculate_background`，对所有像素反复执行 sigma clipping：从当前均值 `B` 和标准差 `σ` 出发，只保留满足 `|I-B| ≤ 2.6σ` 的像素，再更新统计量。这样亮星、异常暗点对背景估计的影响会减小。最终返回两个量：

- `B`：这一帧的整体背景均值，单位与像素值相同；
- `σ`：背景波动的标准差，后续用于设阈值及估算信噪比。

这里估计的是**单个全图背景基准**。如果第一阶段已经做过背景校正，背景在空间上通常更平坦，第二阶段的统一阈值就更容易适用。实现中收敛时返回该轮用于剔除的旧均值和旧标准差，因此复核数值时应以当前代码为准。

### 3.2 按背景噪声设检测阈值

检测阈值为

```text
T = B + kσ
```

其中 `k = 2bkgd_threshold`。程序计算 `A(x,y) = max(I(x,y) - T, 0)`；`A` 大于零的像素进入候选前景。它还会把图像最外侧一圈像素清零，避免边缘像素参与连通域标号。

例如 `B=700`、`σ=8`、`k=5` 时，阈值为 `740`。像素值 `760` 的阈值以上强度是 `20`，像素值 `735` 则不会进入候选前景。`k` 越大，候选通常越少；`k` 越小，弱星更容易进入，但噪声误检也可能增加。这是**像素级检测门槛**，还不是最终星象表的 SNR 门槛。

### 3.3 把相邻前景像素组成一个星象

程序对阈值以上的像素进行连通域标号。一个连通域代表一组相邻的亮像素，即一个候选星象。配置 `2connectivity` 有两种实现：

| 取值 | 行为 |
|---|---|
| `fortran`（默认） | 复现历史三段式标号：首遍赋号、在局部范围内合并部分标签，再用八邻接等价关系合并。 |
| `scipy` | 使用标准八连通标号；斜向接触的前景像素也属于同一个区域。 |

两条路径在普通孤立星象上通常得到类似结果，复杂或相互接触的形状可能存在差异。`fortran` 路径保留历史算法的局部合并及单遍等价标签简化行为，因此不能简单地把它描述成标准 SciPy 八连通的同义实现。这里的“八连通”指像素区域的邻接关系，与第一阶段横向、纵向的中值滤波窗口方向无关。

## 4. 如何得到星象位置、亮度与 SNR

### 4.1 有效测量区域

标号后，程序在距离图像边界约 9 至 10 像素的内部区域累加每个标签的统计量。因而输出中的 `star_pix` 是该内部区域内属于星象的像素数，不一定等于最初连通域标记的全部像素数。最外圈清零与这一测量边界是两道不同的处理。

### 4.2 修正矩定中心

设某个星象内阈值以上强度为 `Aᵢ`，像素列、行坐标分别为 `xᵢ`、`yᵢ`，则中心计算使用权重 `wᵢ = Aᵢ^p`，其中 `p` 取自配置项 `2pos_method`：

```text
x̄ = Σ(xᵢ wᵢ) / Σwᵢ
ȳ = Σ(yᵢ wᵢ) / Σwᵢ
```

`p=1` 是一阶强度加权中心；`p=2` 或 `3` 更强调亮像素。代码输出与历史 Fortran 程序一致的 **1-based 像素坐标**：第一列、第一行从 `1` 开始，而不是 Python 数组的 `0`。星象“亮度”字段 `sumi` 则使用 `ΣAᵢ`，并非 `Σwᵢ`；因此改变 `pos_method` 主要改变中心权重，不直接改变该亮度定义。

### 4.3 像素数量与信噪比

候选星象先受到像素数量限制：当前代码要求 `10 ≤ n ≤ int(π×40²)`，其中 `n` 是前述内部区域的像素数。太小的连通域被视为不可靠，过大的连通域也不会作为普通星象输出。

对通过尺寸限制的候选，程序计算

```text
F   = ΣAᵢ
SNR = F / √(F + nσ²)
```

`F` 是阈值以上强度之和，`σ` 是本帧背景波动。此处 SNR 是本程序采用的筛选指标；它并未从 FITS 头读取增益后建立完整的物理噪声模型。计算出 SNR 后，候选按 `F` 从大到小排序。

## 5. 最终筛选与输出格式

写 `.reg` 文件时，还会检查 `SNR > 2snr_threshold`、`star_pix > 5`、以及未被标记为饱和。由于前一步已经要求 `star_pix ≥ 10`，这里的 `>5` 对当前实现没有额外约束；真正起作用的尺寸下限是 10。SNR 比较使用严格大于，刚好等于门槛的候选不会写出。

对于整型 FITS，代码以 `2^BITPIX-1` 作为饱和判断上限；被标记为饱和的候选不写入最终星表。浮点 FITS 的 `BITPIX` 为负，代码不使用这个整型上限，饱和检查被禁用。因此，使用不同 FITS 数据类型时，饱和过滤行为可能不同。

结果写入同一观测日的 `fits_reg/<原始文件名>.reg`，例如 `fits/A.fit` 对应 `fits_reg/A.fit.reg`。这是可在 DS9 中叠加查看的 region 文本文件，并非新的 FITS 图像。前两行是 DS9 全局样式与 `physical` 坐标系；每个通过筛选的星象占一行 `ellipse`，后面附有中心坐标、积分强度、SNR、标签号、像素数、饱和标记，以及本帧的 `B` 和 `σ`。第三阶段读取其中的像素坐标、亮度和 SNR，与参考星表做匹配。

## 6. 参数怎样影响结果

| 配置项 | 当前代码默认值 | 影响 |
|---|---:|---|
| `2bkgd_threshold` | `5.0` | 乘以背景 `σ` 构成像素级阈值；调高通常减少候选，调低通常增加候选及误检风险。 |
| `2snr_threshold` | `5.0` | 写 `.reg` 时的 SNR 下限；调高会减少最终输出。 |
| `2pos_method` | `2` | 修正矩阶数；高阶更重视中心附近的亮像素。 |
| `2connectivity` | `fortran` | 选择历史标号或标准 SciPy 八连通标号。 |
| `2detect_workers` | `0` | 单日多帧的并行度；`0` 自动最多 2 个进程，并按 FITS 数量、CPU 和可用内存降低并发，`1` 串行。只影响调度方式，不改变算法参数。 |

这些是**代码缺省值**，实际运行以指定的 `.cfg` 为准。例如仓库的 `inputs/configs/nspa2023S0.cfg` 将 `2bkgd_threshold` 设为 `3.5`、`2snr_threshold` 设为 `1.0`、`2pos_method` 设为 `1`，不能把缺省值直接当成该数据集的实际设置。

## 7. 运行与检查

只运行第二阶段可在项目根目录执行：

```powershell
python -m nspa.main --step detect --config inputs/configs/nspa2023S0.cfg
```

启用预处理模式时，应先确认对应的 `fits_n/*_n.fit` 已存在。执行后可检查控制台记录的每帧背景均值、背景 `sigma` 和满足条件的星数，并在 `fits_reg/` 下查看 `.reg`。在 DS9 中把 `.reg` 叠加到对应图像，重点观察弱星漏检、噪点误检、相邻星粘连、边缘目标缺失和饱和星被排除的情况。单看输出星数不足以判断检测质量。

程序在独立的 `spawn` 子进程中运行检测；多帧时还可在该进程内按文件并行，以隔离 Numba 的运行状态。运行汇总写入 `outputs/runs/<run_id>/manifest.json`。若只是需要说明算法，进程隔离不改变上述阈值、连通域和中心计算的含义。

## 8. 一句话概括

**02Detect 把 FITS 图像中高于背景噪声门槛的像素归成候选星象，测出每个星象的中心、强度和 SNR，再筛选成可供 03Match 使用的 `.reg` 星表。**

## 代码依据

- `nspa/core/detector.py`：文件选择、逐帧调度、输出与运行日志。
- `nspa/utils/image_utils.py`：背景估计、阈值分割、连通域及修正矩计算。
- `nspa/io/text_io.py`：最终筛选和 DS9 `.reg` 写出。
- `nspa/config.py`、`nspa/paths.py`：参数缺省值和输入输出路径规则。
